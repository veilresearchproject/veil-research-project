# VEIL MTC + SIGNAL — Offline Evidence Review Pack v0.2

**Engineering test, 28 October 2026.** It is not installed, and it has never reviewed the actual 27 October MTC 90-minute run. The original MTC v0.1.4 recorder remains untouched. All new tests use synthetic inputs, not physical microphones or field evidence.

## New tools since the v0.1 review

- `evidence_review_pack.py`: calls existing v0.1 read-only session validator and SIGNAL sound-level screener, adds a SHA-256 current-file inventory, makes a separate `review.json` file and **editable candidate_review.csv** in a NEW output directory outside the original session.
- Sound-level candidates are **retained even when they coincide with unverified MTC question-playback markers**. Rather than discarding them, each candidate carries `possibly_near_question_marker=true/false/null` (null means the event alignment was not plausible). This avoids suppressing a potentially important coincident recording.
- Optional `--clips` produces short, *derived* PCM WAV excerpts, maximum 20 seconds each, for human listening. No clips are generated by default; no audio uploaded to the internet. Clips cannot be generated if a required inventory file is missing or the scan raises warnings.
- `seam_survey.py`: compares 250-millisecond audio levels on both sides of a split-WAV boundary. Loudness jumps or quiet edges become **review suggestions only**, NEVER claims of continuous or gapless recording.
- Source files are read but never overwritten. Hashes before/after generating the report must match, otherwise finalization fails. A hash made now only identifies the bytes now; it cannot establish what happened during recording.
- Output creation refuses inside the source evidence folder, existing destination folders, unknown destination parents, symbolic-link original files for hashing, and unsupported clip formats. No background service, microphone use, network, AI model, or hardware control.

## Running isolated tests (personal home PC only, or a development sandbox)

Requirements: Python 3.11+ (standard library only) and the `*.py` files in one directory.

```
python -m unittest -v test_offline_review.py test_evidence_review_pack.py test_seam_survey.py
```

## Running on a COPIED completed MTC session (only after reviewing actual JSON log format)

First, make and preserve an untouched copy of the complete session folder. These examples are for a **personal computer**, not AJAX work hardware. They will not be useful until actual MTC event vocabulary and WAV formats have been checked against real session files.

Generate a report and editable candidate table (no derived audio clips):

python evidence_review_pack.py "C:\MTC_COPY\MTC_20261027_215040_70c105" "C:\VEIL_Review_Reports\MTC_review_01"
```

Optional short derived clips, maximum 20 clips by default:

```
python evidence_review_pack.py "C:\MTC_COPY\MTC_20261027_215040_70c105" "C:\VEIL_Review_Reports\MTC_review_02" --clips --max-clips 20 --padding-seconds 2

The destination parent folder must already exist, but the final output subdirectory MUST NOT exist. Never set output inside the evidence source. Review `review.json` for `mtc.issues`, `signal.warnings`, `inventory.issues`, and `seams.boundaries`. The CSV has one row per event for review; no source WAV is altered.

## Human labeling protocol (preliminary)

For each candidate listen with headphones (noting playback level), and compare independent room/camera sound recordings when available. Label **KNOWN_SOURCE**, **UNIDENTIFIED_SOUND**, **SPEECH_LIKE_UNCONFIRMED**, **AUDIO_ARTIFACT**, **NO_EVENT**, or **NEEDS_MORE_REVIEW**. Record observations without jumping to an EVP interpretation; if feasible, ask a second blind reviewer to independently label before revealing the expected question or session context. Keep all negative and rejected cases to compute false-positive rates.

## Explicit scientific and engineering limitations

- No real October 27 MTC file validation; neither actual event JSON schema, normal stop status, questions played, microphone validity nor acoustically heard playback has been checked. Real input may require adapting the parser after reviewing **copies** of the three small session logs.
- SHA-256 fingerprints detect changes **after** this review only if the manifest is retained and independently trusted. They do not authenticate the original acquisition or complete chain of custody. The inventory covers selected named files, not all possible session artifacts or independent camera logs.
- The detector identifies **amplitude changes only**; no speech recognition, words, whisper detection, intentional message detection, anomalous causality, or paranormal/EVP assessment. No detected candidates does not mean there were no sounds. Question-overlap flags are from uncorroborated event markers, not the captured room microphone itself.
- Segment-derived session times use *concatenation as an assumption*. A smooth-looking sound boundary cannot prove no dropped samples or gap. Keep per-file offsets as the reliable navigation coordinates; independent timestamped devices and deliberate seam listening are needed for continuity studies.
- Optional clip exports only support standard 16-bit PCM WAV mono/stereo and can be no more than 20 seconds each. They are secondary derivative assets, **not original evidence**. WAV excerpts could omit context around their edges. All clips and review reports should be clearly labeled derived analysis.
- No Windows home-computer test, no full 90-minute-duration throughput test, no controlled field recordings, no scientific accuracy/false-positive assessment, and no link to remote phone status or SIGNAL's public persona. No changes to GitHub `main` or the active MTC recorder.
